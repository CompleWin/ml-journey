# Способы оценивания степени переобучения моделей

## Переобучение (Overfitting)

**Переобучение** — ситуация, когда модель хорошо работает на обучающих данных, но плохо справляется с новыми, ранее неизвестными примерами.

**Обобщающая способность (Generalization)** — способность модели правильно работать с данными, которые не использовались при обучении.

Для оценки качества модели необходимо проверить:

1. Насколько хорошо модель работает на обучающей выборке.
2. Насколько хорошо модель работает на новых данных.

---

## Отложенная выборка (Hold-out)

**Hold-out** — метод оценки модели путём разделения исходного набора данных на обучающую и тестовую выборки.

![](assets\78f98df187c0ab12074b6c9cc122b54f6e3ba0ac.png)

Например, имеется 1000 объектов:

- **70% (700)** — обучение модели (Train).
- **30% (300)** — проверка модели (Test).

### Алгоритм

1. Случайно разделить исходные данные на две части.
2. Обучить модель на Train.
3. Вычислить ошибку на Train.
4. Вычислить ошибку на Test.
5. Сравнить полученные результаты.

### Интерпретация результатов

| Train Error | Test Error | Вывод                                     |
| ----------- | ---------- | ----------------------------------------- |
| Низкая      | Низкая     | Хорошее обобщение                         |
| Низкая      | Высокая    | Переобучение                              |
| Высокая     | Высокая    | Недообучение или другая проблема качества |

**Недостаток:** результат зависит от случайного разбиения данных. Одно разбиение может оказаться удачным, другое — неудачным.

---

## Скользящий контроль (Leave-One-Out, LOO)

**Leave-One-Out** — метод, при котором модель многократно обучается на всех объектах выборки, кроме одного.

На каждой итерации один объект используется для проверки.

### Пример

Есть 5 объектов: A, B, C, D, E.

| Итерация | Обучение   | Проверка |
| -------- | ---------- | -------- |
| 1        | B, C, D, E | A        |
| 2        | A, C, D, E | B        |
| 3        | A, B, D, E | C        |
| 4        | A, B, C, E | D        |
| 5        | A, B, C, D | E        |

Каждый объект ровно один раз становится проверочным.

Общая оценка качества вычисляется усреднением ошибок на всех проверочных объектах.

![](assets\63f78e5068652870f7350d085c330a6a0cd741f2.png)

### Преимущества

- Почти все данные используются для обучения на каждой итерации.
- Каждый объект участвует в проверке.
- Нет необходимости выбирать одно конкретное разбиение.

### Недостатки

- Требует большого количества обучений.
- При N объектах модель обучается N раз.
- Вычислительно дорогой метод для больших выборок.

---

## Кросс-валидация (Cross-Validation, K-Fold)

**Кросс-валидация** — метод оценки качества модели, при котором исходная выборка разбивается на K групп (фолдов).

На каждой итерации:

- K − 1 групп используются для обучения.
- Одна группа используется для проверки.

<img title="" src="assets\cddc6950ee5e9e036dd088bdeb72f9b0b844d4f1.png" alt="" width="545" data-align="center" />

### Пример: 5-Fold Cross-Validation

Имеется 1000 объектов, разделённых на 5 групп по 200 объектов.

| Итерация | Обучение   | Проверка |
| -------- | ---------- | -------- |
| 1        | 2, 3, 4, 5 | 1        |
| 2        | 1, 3, 4, 5 | 2        |
| 3        | 1, 2, 4, 5 | 3        |
| 4        | 1, 2, 3, 5 | 4        |
| 5        | 1, 2, 3, 4 | 5        |

Получаем пять оценок ошибки:

`E1 = 0.12`

`E2 = 0.10`

`E3 = 0.15`

`E4 = 0.11`

`E5 = 0.12`

Средняя ошибка:

`E = (0.12 + 0.10 + 0.15 + 0.11 + 0.12) / 5 = 0.12`

**Итог:** усреднение результатов позволяет получить более устойчивую оценку качества, чем проверка на одном случайном разбиении.

### Преимущества

- Все объекты участвуют и в обучении, и в проверке на разных итерациях.
- Результат меньше зависит от одного случайного разбиения.
- Требует меньше вычислений, чем Leave-One-Out, если K значительно меньше N.

### Недостаток

- Необходимо обучать модель K раз.

**Важно:** Leave-One-Out — частный случай K-Fold, когда K = N (количество объектов).

## Способы объединения моделей

После многократного обучения можно получить несколько моделей.

В статье рассматриваются два подхода.

### Подход 1. Выбор одной модели

Выбирается модель, показавшая лучшие результаты при проверке.

**Недостаток:** хорошие показатели на конкретной проверочной выборке не гарантируют хорошее качество на новых данных.

### Подход 2. Голосование моделей (Ensemble)

Все обученные модели участвуют в предсказании.

Например, при классификации:

- Модель 1 → Кошка
- Модель 2 → Собака
- Модель 3 → Кошка

Итоговое предсказание: **Кошка**, поскольку за этот класс проголосовало большинство моделей.

**Преимущество:** объединение предсказаний может повысить устойчивость результата.

**Недостаток:** для каждого предсказания необходимо запускать несколько моделей.

**Уточнение:** сама по себе кросс-валидация не требует объединять модели. Обычно её используют для оценки качества и подбора гиперпараметров, после чего обучают итоговую модель на всех доступных обучающих данных.

---

## Сравнение методов

| Метод         | Количество обучений | Особенность                                      |
| ------------- | ------------------- | ------------------------------------------------ |
| Hold-out      | 1                   | Быстрый, но зависит от разбиения                 |
| Leave-One-Out | N                   | Проверяет каждый объект отдельно                 |
| K-Fold        | K                   | Компромисс между качеством оценки и вычислениями |
