## 1. Что вообще пытается сделать этот код?

Представим, что мы читаем английский текст. Языковая модель **Pythia-70m** получает токены текста и обрабатывает их, чтобы предсказывать следующий токен. Внутри модели каждое положение в тексте представлено набором из **512 чисел**. Эти 512 чисел — *активации* (в данном эксперименте — выход одного из слоёв трансформера). Их удобно представлять как координаты точки в пространстве из 512 измерений.

Например, вместо настоящего вектора из 512 чисел вообразим короткий вектор:

```text
x = [1.2, -0.4, 2.1]
```

Это **не три человечески понятных признака** «эмоция», «животное», «действие». Отдельная координата внутреннего представления нейросети может участвовать сразу во многих свойствах текста. Мы хотим построить **вторую, более маленькую по назначению сеть** — *Sparse Autoencoder*, или SAE, — которая научится представлять эти сложные внутренние векторы через набор относительно редких активных признаков.

Схема:

```text
Текст
  ↓
Токенизатор: текст → числовые ID токенов
  ↓
Предобученная Pythia-70m
  ↓
Выход 4-го блока трансформера: вектор из 512 чисел для каждого токена
  ↓
SAE-энкодер: 512 чисел → 2048 оценок потенциальных признаков
  ↓
Top-K: оставить максимум 32 активных значения, остальные заменить нулями
  ↓
SAE-декодер: 2048 чисел → восстановленный вектор из 512 чисел
  ↓
Сравнение восстановленного вектора с исходным и обучение SAE
```

**Ключевое отличие двух моделей:** Pythia уже обучена и в этом ноутбуке **не дообучается**. Обучается только новая сеть SAE. Её задача — не генерировать текст, а **восстанавливать внутренние представления Pythia**.

### Почему из 512 чисел делаем 2048, хотя хотим «сжать» представление?

Здесь «сжатие» означает не уменьшение длины массива, а уменьшение **числа одновременно используемых координат**. Вектор из 2048 чисел хранится в памяти полностью, но после операции Top-K у него не больше 32 ненулевых координат.

- 512 — размерность исходного представления Pythia, `d_model`.
- 2048 — число *кандидатных* признаков в словаре SAE, `d_sae`.
- 32 — максимальное количество активных признаков для одного токена, `k`.
- `2048 / 512 = 4` — словарь в четыре раза шире исходного пространства.
- `32 / 2048 = 0.015625` — активны не более **1,5625%** латентов; не менее **98,4375%** занулены.

Идея называется *разреженным кодированием*: разные токены включают разные небольшие подмножества из большого набора возможных признаков. **Но это ещё не гарантия, что каждому латенту соответствует одно понятное слово или концепция.** Интерпретируемость потребовала бы отдельной проверки.

## 2. Минимальные основы нейросетей, нужные для чтения ноутбука

### 2.1. Что такое токен, эмбеддинг и активация?

**Токен** — элемент, на который токенизатор разбивает текст: слово, часть слова, пробел с частью слова, знак препинания и т. п. Токенизатор сопоставляет каждому токену целое число — *ID*.

**Входной эмбеддинг** — обучаемый вектор, который модель извлекает по ID токена из специальной матрицы. В Pythia-70m его размерность — 512.

**Активация слоя** — вектор чисел, полученный **после преобразований внутри нейросети**. В отличие от входного эмбеддинга, она зависит не только от токена, но и от его контекста, положения и обработки предыдущими слоями.

Например, слово `bank` в предложении о банке и в предложении о берегу реки может иметь одинаковый входной токен и его исходный эмбеддинг, но **разные активации внутренних слоёв**. В этом задании SAE учится на **активациях**, а не на матрице входных эмбеддингов.

### 2.2. Что такое слой, нейрон, вес и смещение?

Для начала представим одно преобразование:

```text
входы: x1 = 2, x2 = 3
веса:  w1 = 4, w2 = -1
смещение: b = 5

результат = 2 × 4 + 3 × (-1) + 5 = 10
```

- **Входы** — числа, переданные преобразованию.
- **Веса** — коэффициенты, определяющие, насколько каждый вход влияет на выход.
- **Смещение** (*bias*) — дополнительная константа, которую можно прибавлять независимо от входов.
- **Параметры** — значения, которые алгоритм обучения может изменять. И веса, и смещения здесь — параметры.
- **Нейрон/латент** в контексте SAE — вычисляемая координата внутри энкодера. Необязательно трактовать её как уже открытый человеческий концепт.

Сеть отличается от этой игрушечной операции прежде всего тем, что подобных преобразований много и они действуют на целые векторы.

### 2.3. Что такое тензор и форма (*shape*)?

Тензор PyTorch — объект, хранящий числа с определённой формой (*shape*):

```python
import torch

scalar = torch.tensor(5.0)                  # shape: []
vector = torch.tensor([1.0, 2.0, 3.0])     # shape: [3]
matrix = torch.tensor([[1., 2.], [3., 4.]]) # shape: [2, 2]
```

Для этого ноутбука особенно важны:

| Форма | Что это означает |
|---|---|
| `[512]` | один вектор активаций одного токена |
| `[64, 512]` | батч из 64 векторов, каждый по 512 чисел |
| `[512, 2048]` | матрица весов энкодера |
| `[64, 2048]` | оценки 2048 признаков для 64 токенов |
| `[2048, 512]` | матрица весов декодера |
| `[512, 128, 512]` | активации 512 текстовых последовательностей, по 128 позиций, 512 чисел в каждой |

Важно: слово **«размерность»** иногда означает число осей массива, а иногда число чисел в векторе. В записи `[64, 512]` у тензора две оси, а длина вектора признаков равна 512.

### 2.4. Как работает обучение нейросети?

**Обучение** — это повторение четырёх действий:

1. Подать примеры в сеть.
2. Посчитать её предсказания и **ошибку** (*loss*).
3. Вычислить, как изменение каждого параметра повлияет на ошибку (**градиенты**).
4. Немного изменить параметры в направлении уменьшения ошибки (**шаг оптимизатора**).

Простой одномерный пример. Мы хотим, чтобы число `w` приблизилось к `3`. Ошибка:

```text
L(w) = (3 - w)²
```

Если `w = 1`, ошибка равна `4`. Производная по `w` равна `2(w - 3) = -4`. При скорости обучения `0.1` градиентный шаг даст:

```text
новое w = 1 - 0.1 × (-4) = 1.4
новая ошибка = (3 - 1.4)² = 2.56
```

То есть ошибка уменьшилась. В реальном SAE параметров более двух миллионов, поэтому вычислением производных занимается **автоматическое дифференцирование PyTorch — autograd**.

## 3. Формула Sparse Autoencoder: сначала числа, потом матрицы

### 3.1. Энкодер отвечает на вопрос «какие признаки активны?»

Пусть у нас вход `x = [2, 1]`, а энкодер сравнивает его с тремя направлениями:

```text
признак A: 1 × 2 + 0 × 1 = 2
признак B: 0 × 2 + 1 × 1 = 1
признак C: 1 × 2 + 1 × 1 = 3
```

Получаем три оценки:

```text
pre_acts = [2, 1, 3]
```

Предположим, `k = 2`. Оставляем **две наибольшие** оценки (`3` и `2`):

```text
acts = [2, 0, 3]
```

Позиция признака B занулена. Если бы признаков было 2048, оставили бы максимум 32.

Теперь то же на матрицах:

```text
x = [2, 1]                        форма [1, 2]

W_enc = [[1, 0, 1],
         [0, 1, 1]]               форма [2, 3]

x @ W_enc = [2, 1, 3]            форма [1, 3]
```

Символ `@` в Python — **матричное умножение**. В отличие от поэлементного `*`, оно вычисляет для каждого столбца матрицы сумму произведений. Например, для третьего столбца получается `2 × 1 + 1 × 1 = 3`.

### 3.2. Декодер отвечает на вопрос «какой исходный вектор этим признакам соответствует?»

Для каждого признака существует свой вектор в **исходном пространстве**. Возьмём:

```text
W_dec = [[1.0, 0.0],    # вклад признака A
         [0.0, 1.0],    # вклад признака B
         [0.2, 0.4]]    # вклад признака C
```

У нас активны A со значением `2` и C со значением `3`, поэтому восстановленный вектор:

```text
x_hat = 2 × [1.0, 0.0] + 0 × [0.0, 1.0] + 3 × [0.2, 0.4]
      = [2.0, 0.0] + [0.0, 0.0] + [0.6, 1.2]
      = [2.6, 1.2]
```

Исходный вектор `x = [2, 1]`. Ошибки по координатам:

```text
x - x_hat = [-0.6, -0.2]
```

Средний квадрат ошибки (MSE):

```text
MSE = ((-0.6)² + (-0.2)²) / 2
    = (0.36 + 0.04) / 2
    = 0.20
```

При обучении веса изменяются, чтобы реконструкция приближалась к исходному вектору.

### 3.3. Теперь полная математическая запись

Энкодер в исходном ноутбуке:

```text
pre_acts = x @ W_enc + b_enc
acts = TopK(pre_acts)
x_hat = acts @ W_dec + b_dec
```

- `x`: входная строка из 512 чисел.
- `W_enc`: матрица `[512, 2048]`, её **столбец** задаёт веса одного латента энкодера.
- `b_enc`: 2048 смещений, по одному на латент.
- `pre_acts`: оценки каждого из 2048 латентов **до Top-K**.
- `TopK`: оставить значения выбранных `k` наибольших координат в исходных позициях, остальные заменить нулём.
- `acts`: разреженный вектор `[2048]`.
- `W_dec`: матрица `[2048, 512]`, её **строка** задаёт вектор одного латента в исходном пространстве.
- `b_dec`: вектор смещения `[512]`.
- `x_hat` (читается «икс с крышкой»): восстановленный вектор из 512 чисел.

Для батча из 64 примеров всё то же самое, но вместо `[512]` получаем входную матрицу `[64, 512]` и аналогично добавляется первая ось в выходах.

## 6. Ячейка 2: `BrokenTopKSAE`, первая версия сети

### 6.1. Объявление класса

```python
class BrokenTopKSAE(nn.Module):
    def __init__(self, d_model=512, d_sae=2048, k=32):
        super().__init__()
```

`class` создаёт новый тип объекта; `BrokenTopKSAE` — имя класса. Наследование `nn.Module` сообщает PyTorch, что объект — нейросетевая модель, содержащая обучаемые параметры. `__init__` вызывается при создании экземпляра. `super().__init__()` инициализирует базовую часть `nn.Module`, которая умеет отслеживать параметры и подмодули.

`d_model`, `d_sae`, `k` — значения по умолчанию. Их можно переопределять, создавая экземпляр. В этом ноутбуке они равны 512, 2048 и 32.

### 6.2. Создание параметров

```python
self.k = k
self.W_enc = nn.Parameter(torch.randn(d_model, d_sae) * 0.02)
self.b_enc = nn.Parameter(torch.zeros(d_sae))
self.W_dec = nn.Parameter(torch.randn(d_sae, d_model) * 0.02)
self.b_dec = nn.Parameter(torch.zeros(d_model))
```

**`self`** означает текущий объект. Поэтому `self.W_enc` — хранимая внутри объекта матрица.

**`torch.randn(512, 2048)`** создаёт матрицу формы `[512, 2048]`, элементы которой случайно выбраны из стандартного нормального распределения (вокруг 0 с типичным разбросом около 1). Умножение `* 0.02` уменьшает масштаб исходных весов примерно в 50 раз; оно **не** означает, что веса навсегда останутся такими маленькими.

**`torch.zeros(2048)`** создаёт 2048 нулей. Вначале смещения энкодера равны нулю. Аналогично, 512 нулей для декодера.

**`nn.Parameter(...)`** превращает тензор в зарегистрированный обучаемый параметр модели. Поэтому `net.parameters()` впоследствии найдёт эти четыре объекта, а оптимизатор сможет их изменять.

Размеры:

| Параметр | Форма | Число скаляров | Роль |
|---|---|---:|---|
| `W_enc` | `[512, 2048]` | 1 048 576 | из входных координат в оценки латентов |
| `b_enc` | `[2048]` | 2 048 | пороги/смещения латентов |
| `W_dec` | `[2048, 512]` | 1 048 576 | из латентов в исходные координаты |
| `b_dec` | `[512]` | 512 | фоновое смещение восстановления |
| **Всего** | — | **2 099 712** | обучаемые параметры SAE |

Это количество параметров **самого SAE**, а не 70 миллионов параметров предобученной Pythia.

### 6.3. Метод `encode`

```python
def encode(self, x):
    pre_acts = x @ self.W_enc + self.b_enc
    val, idx = torch.topk(pre_acts, self.k, dim=-1)
    acts = torch.zeros_like(pre_acts).scatter_(-1, idx, val)
    return acts
```

Разбираем последовательно:

**Строка 1: `pre_acts = ...`**

Если `x` имеет форму `[64, 512]`, то умножение `[64, 512] @ [512, 2048]` даёт `[64, 2048]`. У каждого из 64 токенов теперь есть оценка каждого из 2048 латентов.

`+ self.b_enc` добавляет вектор `[2048]` **к каждой из 64 строк**. PyTorch выполняет это автоматически с помощью *broadcasting* (вещания) — логического повторения меньшего массива вдоль подходящей оси, не требующего написать явный цикл.

**Строка 2: `torch.topk(..., dim=-1)`**

`dim=-1` — последняя ось, здесь ось 2048 латентов. Для **каждой строки отдельно** PyTorch выбирает 32 наибольших числа.

- `val` содержит выбранные **значения**, форма `[64, 32]`.
- `idx` содержит их **индексы**, форма `[64, 32]`.

Например:

```text
pre_acts = [0.4, 2.0, -0.5, 1.1]
k = 2
val = [2.0, 1.1]
idx = [1, 3]
```

**Строка 3: `zeros_like(...).scatter_(...)`**

`torch.zeros_like(pre_acts)` создаёт массив нулей такой же формы `[64, 2048]`. `scatter_` вставляет выбранные значения на места с индексами `idx` вдоль последней оси:

```text
нулевой массив: [0.0, 0.0, 0.0, 0.0]
индексы:        [1, 3]
значения:       [2.0, 1.1]
результат:      [0.0, 2.0, 0.0, 1.1]
```

Подчёркивание в конце имени `scatter_` в PyTorch обычно означает **операцию на месте** (*in-place*): изменяется сам тензор, на котором вызвали метод.

`return acts` возвращает разреженные активации.

**Первая проблема:** `topk` выбирает **самые большие числа, но не требует, чтобы они были положительными**. Если оценки равны `[-2, -3, -4]` при `k=2`, сломанный вариант оставляет `[-2, -3, 0]` с учётом исходных позиций. Для распространённой реализации неотрицательных признаков Top-K SAE это нежелательно. Исправленная версия пропускает выбранные значения через `ReLU`.

### 6.4. Метод `decode`

```python
def decode(self, acts):
    return acts @ self.W_dec + self.b_dec
```

Если `acts` имеет форму `[64, 2048]`, то `[64, 2048] @ [2048, 512]` даёт `[64, 512]`. Это **восстановленные активации Pythia**, а не вероятность слов и не текст.

У каждого из 2048 латентов есть собственная **строка** в `W_dec` длиной 512. При восстановлении эти строки складываются с коэффициентами, равными значениям активных латентов.

### 6.5. Метод `forward`

```python
def forward(self, x):
    acts = self.encode(x)
    x_hat = self.decode(acts)
    return x_hat, acts
```

`forward` описывает полный проход входа через модель: **закодировать → декодировать**. Когда мы вызываем `net(x)`, `nn.Module` запускает `forward` (а не только «обычный» вызов функции). Возвращаются **два объекта**: `x_hat` для измерения ошибки, `acts` для оценки использования латентов.

## 7. Ячейка 3: получение обучающих примеров из Pythia

До этого мы только **описали архитектуру**. Нейросети SAE нужны реальные входные векторы `x`. Их берут из предобученной языковой модели.

### 7.1. Настройка вычислений и загрузка Pythia

```python
torch.set_num_threads(4)

name = 'EleutherAI/pythia-70m'
model = AutoModelForCausalLM.from_pretrained(name).eval()
tokenizer = AutoTokenizer.from_pretrained(name)
```

- `torch.set_num_threads(4)` ограничивает до 4 число CPU-потоков, которые PyTorch использует для ряда операций. Это **не число слоёв, не число обучающих эпох и не размер батча**.
- `name` — идентификатор готовой модели в Hugging Face.
- `from_pretrained(name)` загружает архитектуру и **уже обученные веса** Pythia.
- `.eval()` переводит Pythia в режим оценки (например, отключает dropout, если он есть). **Сам по себе `.eval()` не отключает вычисление градиентов**; это отдельно обеспечит `torch.inference_mode()`.
- `AutoTokenizer.from_pretrained(name)` загружает токенизатор, совместимый с моделью.

### 7.2. Получение и токенизация корпуса

```python
texts = load_dataset('NeelNanda/pile-10k', split='train')['text'][:10000]
tokens = tokenizer(texts, truncation=True, max_length=128)['input_ids']
sequences = [t for t in tokens if len(t) == 128][:512]
ids = torch.tensor(sequences)
```

Это читается так:

1. Загрузить обучающую часть набора текстов `NeelNanda/pile-10k`.
2. Взять первые 10 000 текстов.
3. Превратить тексты в последовательности **целых ID токенов**.
4. Ограничить каждую последовательность **не более чем 128 токенами**: длинные усекаются.
5. Оставить только последовательности, в которых получилось **ровно 128 ID**; короткие исключаются.
6. Взять первые 512 подходящих последовательностей.
7. Составить из них целочисленный тензор `ids` формы `[512, 128]`.

Обратите внимание: это **не случайные 512 текстов из датасета**, а первые 512 после фильтрации. Здесь не создаётся отдельная валидационная выборка.

### 7.3. Почему нужен `hook`?

Обычно при использовании языковой модели нас интересуют **итоговые оценки следующего токена**. Но SAE нужны **внутренние активации одного промежуточного слоя**. `register_forward_hook` позволяет «подслушать» выход выбранного модуля во время обычного прямого прохода модели, не переписывая её архитектуру.

```python
saved = []

def hook(module, inputs, outputs):
    if isinstance(outputs, (tuple, list)):
        outputs = outputs[0]
    saved.append(outputs.detach().cpu())
```

- `saved = []` — список для собранных батчей активаций.
- `module` — модуль, чей выход отслеживается.
- `inputs` — входы этого модуля; в функции они не используются.
- `outputs` — его выход.
- У некоторых модулей выход представлен **кортежем/списком**. Тогда `[0]` выбирает основной тензор с активациями. Это предположение согласуется с тем, как здесь используется слой Pythia.
- `.detach()` разрывает связь с графом вычисления градиентов: дальше мы храним **данные**, а не инструкции для обратного прохода по Pythia.
- `.cpu()` обеспечивает хранение тензора на CPU.
- `saved.append(...)` кладёт очередной батч активаций в список.

**Аналогия:** как датчик, установленный на промежуточном участке конвейера. Конвейер по-прежнему выполняет свою работу, а датчик записывает промежуточный результат.

### 7.4. К какому слою подключён датчик?

```python
layer = 3
handle = model.gpt_neox.layers[layer].register_forward_hook(hook)
```

Индексация Python начинается с **нуля**, поэтому `layers[3]` — **четвёртый по счёту блок** трансформера. Хук регистрируется на выходе этого блока. `handle` — объект, с помощью которого затем можно снять хук.

Важно различать «четвёртый блок» и «слой с индексом 3»: в коде записан именно индекс `3`.

### 7.5. Пропускаем тексты через модель, не обучая её

```python
try:
    with torch.inference_mode():
        for batch in ids.split(16):
            model.gpt_neox(batch, use_cache=False)
finally:
    handle.remove()
```

- `ids.split(16)` режет 512 последовательностей на батчи максимум по 16: здесь получается 32 батча.
- Каждый `batch` имеет форму `[16, 128]` и содержит ID токенов.
- `model.gpt_neox(batch, use_cache=False)` запускает **трансформерную часть** Pythia, внутри которой сработает хук. Выход самого вызова не сохраняется: нас интересует значение из `hook`.
- `use_cache=False` отключает использование KV-кэша; здесь мы не занимаемся генерацией по одному токену.
- `torch.inference_mode()` отключает построение вычислительного графа для этого прохода, экономит ресурсы; Pythia не обучается.
- Конструкция `try/finally` гарантирует `handle.remove()` даже при ошибке, чтобы хук не оставался включённым.

**Какой тензор перехватывается?** Для одного батча — примерно `[16, 128, 512]`: 16 текстов, 128 позиций в каждом, 512 координат активации для каждой позиции. После 32 проходов список `saved` содержит 32 таких тензора.

### 7.6. Сборка общей матрицы активаций

```python
X = torch.cat(saved)[:, 1:].reshape(-1, 512)
print(f'Активации: {X.shape}')
assert len(X) == len(ids) * 127
torch.save(X, "pythia_activations.pt")
```

Здесь в одной строке скрыто три операции:

**1. `torch.cat(saved)` — склеить батчи по первой оси.**

```text
32 батча по [16, 128, 512]
                ↓ склеивание
         [512, 128, 512]
```

**2. `[:, 1:]` — удалить первую позицию в каждой последовательности.**

- Первое `:` означает «взять все 512 последовательностей».
- `1:` означает «взять позиции с индексами 1, 2, ..., 127», то есть **127 позиций вместо 128**.
- Последняя ось из 512 чисел остаётся нетронутой.

Итоговая форма `[512, 127, 512]`. Код **не объясняет, почему исключена первая позиция**. Не следует без проверки утверждать, что это обязательно BOS или иной специальный токен.

**3. `.reshape(-1, 512)` — превратить последовательности и позиции в один общий список токенов.**

Число строк определится автоматически (`-1`):

```text
[512 последовательностей, 127 позиций, 512 координат]
                      ↓
[512 × 127 = 65 024 строк, 512 координат]
```

То есть:

```text
X.shape = [65024, 512]
```

**Каждая строка `X` — один внутренний вектор Pythia для одной позиции токена в контексте.** Это и есть обучающие примеры для SAE. Одна строка **не** равна одному исходному тексту или одному постоянному эмбеддингу из словаря.

`assert` проверяет число строк: если оно не совпадёт с ожиданием, программа остановится. `torch.save` записывает тензор на диск как `pythia_activations.pt` — его можно использовать повторно, не прогоняя Pythia заново.

**Что реально напечатал ноутбук:**

```text
Активации: torch.Size([65024, 512])
```

В памяти при формате `float32` только эти числа занимают приблизительно **127 МиБ** (`65024 × 512 × 4` байта), без учёта остальных объектов.

## 9. Ячейка 5: как обучают SAE и оценивают результат

Ниже самая важная часть эксперимента: она впервые **изменяет веса SAE**.

### 9.1. Оптимизатор и служебные переменные

```python
def train_sae(net, X):
    optimizer = torch.optim.Adam(net.parameters(), lr=1e-3)
    ev_history = []
    seen = torch.zeros(2048, dtype=torch.bool)
```

- `train_sae(net, X)` — функция принимает модель SAE и набор входов `X`.
- `net.parameters()` возвращает обучаемые веса и смещения SAE (`W_enc`, `b_enc`, `W_dec`, `b_dec`).
- `torch.optim.Adam(...)` создаёт **оптимизатор Adam**, который будет обновлять параметры на основе градиентов. В отличие от самого простого градиентного спуска, Adam использует накопленную информацию о прошлых градиентах для адаптации шага.
- `lr=1e-3` означает `0.001` — базовую *скорость обучения* (*learning rate*).
- `ev_history = []` — сюда будут записываться значения метрики объяснённой дисперсии.
- `seen` — булев вектор длины 2048, вначале все значения `False`: «данный латент ещё ни разу не активировался в оцениваемом окне».

Здесь длина `seen` **жёстко зашита как 2048**. Для моделей с другим `d_sae` функцию пришлось бы адаптировать.

### 9.2. Цикл из 1000 шагов

```python
for step in range(1000):
    x = X[torch.randint(len(X), (64,))]
    x_hat, acts = net(x)
    loss = (x - x_hat).square().mean()
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
```

**Шаг 1: `for step in range(1000)`**

Выполнить 1000 итераций с номерами от `0` до `999`. Один *шаг* здесь — одна случайная мини-подборка и одно обновление параметров. **Это не 1000 эпох**: эпоха означала бы обработку всей обучающей выборки.

**Шаг 2: `torch.randint(len(X), (64,))`**

Выбрать 64 случайных целых индекса из диапазона от `0` до `65023`. Затем `X[...]` достаёт по ним 64 строки. Итоговая форма `x` — `[64, 512]`.

Выбор происходит **с возвращением**: индексы могут повториться даже в одном батче. За 1000 шагов модель обрабатывает `1000 × 64 = 64 000` *предъявлений примеров*, но не обязательно 64 000 разных строк.

**Шаг 3: `x_hat, acts = net(x)`**

PyTorch вызывает `forward`: сначала получает `acts` формы `[64, 2048]`, затем `x_hat` формы `[64, 512]`. Эта операция пока **не меняет параметры**.

**Шаг 4: `loss = (x - x_hat).square().mean()`**

Вычислить среднюю квадратичную ошибку — *Mean Squared Error*, MSE.

```text
x - x_hat      → ошибки всех элементов [64, 512]
.square()      → квадраты ошибок, чтобы отрицательные не компенсировали положительные
.mean()        → среднее из 64 × 512 = 32 768 квадратов
```

Операция возвращает **одно число** — функцию потерь. Математически:

```text
L = сумма квадратов всех 64 × 512 ошибок / (64 × 512)
```

Если громоздкая запись непривычна, прочитай её обратно: *для каждой строки и каждой координаты найти разность; возвести её в квадрат; сложить все 32 768 квадратов; разделить на 32 768*.

**Шаг 5: `optimizer.zero_grad()`**

Очистить ранее накопленные градиенты параметров. PyTorch по умолчанию **суммирует** градиенты, поэтому перед новым шагом их обычно обнуляют.

**Шаг 6: `loss.backward()`**

По вычислительному графу вычислить производные `loss` по всем параметрам SAE, участвовавшим в прямом проходе. Полученные значения попадают в `.grad` соответствующих параметров. Это **ещё не изменение весов**.

**Шаг 7: `optimizer.step()`**

Adam использует градиенты, чтобы обновить веса и смещения. Только здесь параметры меняются.

**Важная тонкость Top-K:** через `topk` и `scatter_` PyTorch проводит градиент к **выбранным значениям**; координаты, обнулённые маской, в этом проходе обычно не получают прямого полезного градиента от реконструкции. Поэтому латент, который почти никогда не выбирается, легко становится «мёртвым».

### 9.3. Почему метрики считают после 500-го шага?

```python
if step >= 500:
    with torch.no_grad():
        ev = 1 - (x - x_hat).var(dim=-1, unbiased=False).mean() / x.var(dim=-1, unbiased=False).mean().clamp_min(1e-12)
        ev_history.append(ev.item())
        seen |= (acts != 0).any(dim=0)
```

Шаги `0–499` используются только для обучения, а в шагах `500–999` **и обучение продолжается, и собираются метрики**. Это не валидация на новых данных. Всего сохраняется 500 значений EV.

`torch.no_grad()` означает: операции оценки метрик не надо записывать в граф градиентов.

Важно: метрики вычисляются по `x_hat` и `acts`, полученным **до** вызова `optimizer.step()` в текущем шаге. Это небольшая временная особенность реализации, потому что оценивание находится после обновления, а пересчёта `net(x)` нет.

#### Explained Variance (EV) — насколько хорошо сохраняется разброс значений?

В ноутбуке метрика задаётся так:

```text
EV = 1 - (средняя по 64 токенам дисперсия 512 координат ошибки)
         / (средняя по 64 токенам дисперсия 512 координат входа)
```

**Перевод на обычный язык:**

1. Для каждого входного вектора из 512 чисел посчитать, насколько его координаты разбросаны относительно среднего — это дисперсия `x`.
2. Найти вектор ошибок `x - x_hat`, посчитать дисперсию его 512 координат.
3. Усреднить дисперсии по 64 токенам.
4. Разделить среднюю дисперсию ошибок на среднюю дисперсию исходных векторов.
5. Вычесть отношение из 1.

**Что делают отдельные операции?**

- `.var(dim=-1, unbiased=False)` — дисперсия **вдоль последней оси**, то есть среди 512 координат **каждой строки**. `unbiased=False` задаёт деление на число координат `512`, а не на `511`.
- `.mean()` — среднее из 64 получившихся дисперсий.
- `.clamp_min(1e-12)` — защищает знаменатель от деления на ноль, заменяя слишком маленькие значения минимумом `0.000000000001`.
- `1 - ...` — переводит отношение ошибок в показатель качества.
- `.item()` превращает скалярный тензор в обычное Python-число.

**Пример на двух координатах:**

```text
x = [1, 3]
x_hat = [1, 2]
ошибка = x - x_hat = [0, 1]

среднее x = 2
Var(x) = ((1 - 2)² + (3 - 2)²) / 2 = 1

среднее ошибки = 0.5
Var(ошибки) = ((0 - 0.5)² + (1 - 0.5)²) / 2 = 0.25

EV = 1 - 0.25 / 1 = 0.75 = 75%
```

Интерпретация: при такой формуле дисперсия оставшейся ошибки составляет четверть дисперсии исходного вектора.

**Осторожно: EV — не то же самое, что MSE.** Например, если ко всем координатам восстановленного вектора прибавить одинаковую ошибку `+10`, вектор ошибок будет постоянным `[-10, -10, ...]`: его дисперсия равна нулю, поэтому EV может стать 100%, хотя реконструкция ужасна по MSE. Кроме того, здесь дисперсия считается **между координатами внутри токена**, а не между примерами по каждой координате. Поэтому важно знать конкретную реализацию метрики, а не только её название.

#### Dead Latents Ratio — сколько латентов ни разу не использовалось?

```python
seen |= (acts != 0).any(dim=0)
```

Это строка из трёх операций:

1. `acts != 0` — для каждого из 64 токенов и 2048 латентов получить `True`, если активация **ненулевая**; форма `[64, 2048]`.
2. `.any(dim=0)` — проверить для **каждого латента**, активировался ли он хотя бы на одном из 64 токенов текущего батча; форма `[2048]`.
3. `seen |= ...` — логическое «ИЛИ» с ранее накопленными значениями; `True` останется `True` до конца окна измерения.

Маленький пример:

```text
           латент A   латент B   латент C   латент D
токен 1:      2.0        0.0        0.0        0.0
токен 2:      0.0        1.3        0.0        0.0
токен 3:      0.0        0.0        0.0        0.0

any по строкам:
seen =         True       True       False      False
```

Два из четырёх латентов «мёртвые» **в наблюдаемом окне**: 50%. Если один из них включится в следующем батче, его отметка станет `True`.

Измерение охватывает **последние 500 шагов × 64 предъявления = 32 000 токеновых примеров** (с возможными повторами). «Мёртвый» здесь — **строго операционное** определение: не имел ненулевой активации в этом окне. Это не доказательство, что он не смог бы активироваться на любом мыслимом тексте.

### 9.4. Что функция возвращает?

```python
return sum(ev_history) / 500, (~seen).float().mean().item()
```

- `sum(ev_history) / 500` — среднее из 500 оценок EV, то есть **не** EV по всему корпусу и **не** значение на одном финальном батче.
- `~seen` — логическое НЕ: `True` для никогда не включившихся латентов.
- `.float()` — перевести `True` в `1.0`, а `False` в `0.0`.
- `.mean()` — среднее этих 2048 нулей и единиц, то есть доля мёртвых латентов.
- `.item()` — превратить результат в Python-число.

### 9.5. Запуск сломанной сети

```python
broken = BrokenTopKSAE()
ev_bad, dead_bad = train_sae(broken, X.float())
print(f'Broken: Explained Variance = {ev_bad:.1%}, Dead Latents = {dead_bad:.1%}')
```

`BrokenTopKSAE()` создаёт объект с начальными случайными весами. `X.float()` приводит входы к формату `float32`, который согласуется с типом параметров модели. После обучения возвращаются две метрики.

Записанный в ноутбуке вывод:

```text
Broken: Explained Variance = 82.9%, Dead Latents = 27.2%
```

**Принципиально важно:** исходная модель **не провалила порог EV ≥ 80%** из задания — её EV уже 82,9%. Однако по требованию **Dead Latents ≤ 5%** она провалилась: 27,2% — примерно **557 из 2048** потенциальных признаков. Это не признак хорошего покрытия словаря.

## 10. Ячейка 6: чем `FixedTopKSAE` отличается от первой версии?

Главное: модель по-прежнему выполняет **энкодирование → Top-K → декодирование**. Изменена **геометрия весов**, **начальное смещение**, **обработка отрицательных активаций** и **нормировка декодера**.

### 10.1. Создание единичных направлений для декодера

```python
W = torch.randn(d_sae, d_model)
W = W / W.norm(dim=1, keepdim=True)
```

`W` имеет форму `[2048, 512]`: 2048 направлений в 512-мерном пространстве. Все числа сначала случайны.

**Зачем нормировать строки?** Представим два вектора:

```text
v = [3, 4]
длина v = sqrt(3² + 4²) = sqrt(25) = 5
нормированный v = [3/5, 4/5] = [0.6, 0.8]
его длина = sqrt(0.6² + 0.8²) = 1
```

Длина вектора `[v1, ..., v512]` вычисляется как корень из суммы квадратов его элементов. Это **L2-норма**. `W.norm(dim=1, keepdim=True)` вычисляет длину **каждой из 2048 строк**; результат имеет форму `[2048, 1]` благодаря `keepdim=True`. Деление `[2048, 512] / [2048, 1]` автоматически делит каждую строку на её собственную длину.

Теперь каждое направление декодера имеет L2-норму 1 **на момент инициализации**.

### 10.2. Энкодер изначально согласован с декодером

```python
self.W_enc = nn.Parameter(W.T.clone())
self.b_enc = nn.Parameter(torch.zeros(d_sae))
self.W_dec = nn.Parameter(W.clone())
self.b_dec = nn.Parameter(x_mean.clone())
```

- `W` — `[2048, 512]`.
- `W.T` — **транспонирование**: поменять строки со столбцами, получить `[512, 2048]`.
- `.clone()` — создать отдельную копию значений.

Изначально `W_enc` — транспонированная копия `W_dec`. Это означает, что **каждый признак ищется примерно в том же направлении, которое затем используется для его восстановления**.

**Тонкость:** после `nn.Parameter(W.T.clone())` и `nn.Parameter(W.clone())` получаются **две независимые обучаемые матрицы**. В ходе обучения равенство `W_enc = W_dec.T` **не поддерживается автоматически**. Это *согласованная инициализация*, а не постоянно связанные (*tied*) веса.

### 10.3. Почему `b_dec` равно среднему входу?

При создании исправленной модели ей передаётся `x_mean` — вектор из 512 средних значений всех обучающих активаций.

Представим, что некоторые векторы имеют большой общий фон:

```text
x1 = [10, 20]
x2 = [12, 18]
среднее = [11, 19]

x1 - среднее = [-1, 1]
x2 - среднее = [1, -1]
```

Вместо того чтобы учить словарь заново объяснять общий фон `[11, 19]` для каждого примера, можно представить данные как **среднее + отклонение**. Тогда SAE сосредотачивается на изменяющейся части.

Если сеть пока вообще ничего не восстановила, `acts = 0`, декодер возвращает `b_dec`, то есть **средний вектор**, а не нулевой. При наличии сильного общего смещения это может резко улучшить начальное приближение.

Важно: `b_dec` всё ещё объявлен через `nn.Parameter`, поэтому **он тоже обучается**. Он не остаётся равным среднему навсегда.

### 10.4. Энкодер учитывает центрирование и ReLU

```python
def encode(self, x):
    pre_acts = (x - self.b_dec) @ self.W_enc + self.b_enc
    val, idx = torch.topk(pre_acts, self.k, dim=-1)
    acts = torch.zeros_like(pre_acts).scatter_(-1, idx, torch.relu(val))
    return acts
```

Отличия от первой версии:

**Первое:** `(x - self.b_dec)` — энкодер анализирует **отклонение от фонового уровня**, а не абсолютные координаты. Это согласовано с тем, что декодер потом добавляет `b_dec` обратно.

**Второе:** `torch.relu(val)` применяет **ReLU** к отобранным числам. Её правило:

```text
ReLU(-5) = 0
ReLU(-0.2) = 0
ReLU(0) = 0
ReLU(3) = 3
```

То есть `ReLU(z) = max(0, z)`.

Это создаёт **неотрицательные активации латентов**. Но `topk` всё ещё сначала выбирает 32 наибольших *сырых* значения, поэтому после ReLU **может остаться меньше 32 ненулевых активаций**. Нельзя строго говорить «всегда ровно 32 активных латента»; верно «не более 32».

**Почему нельзя просто сделать отрицательные числа положительными модулем?** Потому что `abs(-5)=5` исказило бы смысл: сильная отрицательная оценка стала бы очень сильной положительной активацией. ReLU вместо этого считает отрицательный сигнал отсутствием активации данного неотрицательного признака.

### 10.5. Декодер нормирует свои направления при каждом прямом проходе

```python
def decode(self, acts):
    return acts @ (self.W_dec / self.W_dec.norm(dim=1, keepdim=True)) + self.b_dec
```

Вместо сырой `W_dec` используется **нормированная по строкам матрица**. В результате эффективный вектор каждого признака имеет длину 1 во время вычисления реконструкции.

**Почему это полезно?** Без ограничения декодер может произвольно увеличивать длину одного вектора и компенсировать это уменьшением активации соответствующего латента. Тогда масштаб латента и геометрический смысл направления становятся неустойчивыми. Нормировка исключает эту простую свободу масштаба **для эффективных строк декодера**.

Обратите внимание: код нормирует строки **в выражении**, а не переписывает сами хранимые параметры `W_dec` после каждого шага оптимизатора. По этому выражению PyTorch также рассчитывает градиенты. В нём отсутствует маленький `eps` в знаменателе: теоретически полностью нулевая строка вызвала бы деление на ноль, хотя со случайной инициализацией это не ожидаемое начальное состояние.

### 10.6. Все изменения в одной таблице

| Компонент | `BrokenTopKSAE` | `FixedTopKSAE` | Зачем |
|---|---|---|---|
| Начальные веса энкодера и декодера | независимые случайные | транспонированно согласованы при инициализации | искать и восстанавливать признаки согласованными направлениями |
| Начальные векторы декодера | маленькие случайные, без единичной нормы | случайные единичные направления | предсказуемая начальная геометрия |
| Вход энкодера | `x` | `x - b_dec` | анализ отклонений от среднего |
| Активации после Top-K | могут быть отрицательными | `ReLU(val)` даёт неотрицательные | более стандартная интерпретация присутствия признака |
| Декодер при вычислении | сырая `W_dec` | нормированная по строкам `W_dec` | фиксировать эффективный масштаб направлений |
| Начальное `b_dec` | нулевой вектор | средний входной вектор | лучше восстанавливать общий фон |

Это **пакет изменений**, поэтому по одному эксперименту невозможно узнать, какое именно изменение обеспечило основную часть улучшения. Для этого потребовалось бы *ablation study*: исправлять по одному пункту и сравнивать результаты при одинаковых условиях.

## 11. Ячейка 7: обучение исправленной модели

```python
fixed = FixedTopKSAE(X.float().mean(dim=0))
ev_good, dead_good = train_sae(fixed, X.float())
print(f'Fixed: Explained Variance = {ev_good:.1%}, Dead Latents = {dead_good:.1%}')
```

**`X.float().mean(dim=0)`**: матрица `X` имеет форму `[65024, 512]`. Выражение `mean(dim=0)` усредняет **по строкам**, отдельно для каждой из 512 координат, и возвращает вектор формы `[512]`. Это то самое `x_mean`, которое используется как начальное смещение декодера.

`FixedTopKSAE(...)` создаёт модель; `train_sae` обучает её **той же функцией**, с 1000 шагами и батчами по 64. Значит, отличия результата в этом запуске связаны с **архитектурой и инициализацией**, а не с отдельным алгоритмом обучения. Но случайные веса и батчи в двух запусках тоже отличаются, поскольку фиксированного seed нет.

Записанный результат:

```text
Fixed: Explained Variance = 84.4%, Dead Latents = 0.0%
```

### 11.1. Сопоставление результатов

| Метрика | Broken | Fixed | Изменение |
|---|---:|---:|---:|
| Explained Variance | 82,9% | 84,4% | +1,5 процентного пункта |
| Dead Latents Ratio | 27,2% | 0,0% (как напечатано) | −27,2 процентного пункта |
| Выполняется требование EV ≥ 80%? | Да | Да | — |
| Выполняется требование Dead Latents ≤ 5%? | Нет | Да | — |

**Почему исправленная сеть лучше, хотя EV выросла лишь немного?** Потому что она достигла сравнимого качества реконструкции, задействовав **значительно больше элементов своего словаря**. У сломанной сети реконструкция могла быть приемлемой даже при том, что сотни латентов никогда не использовались.

Есть две оговорки:

- Вывод `0.0%` **округлён до одной цифры после запятой**; он не доказывает с полной точностью, что мёртвых латентов буквально ноль. Для проверки можно вывести `dead_good` с большей точностью или посчитать точное число.
- Эти цифры получены в одном **недетерминированном** запуске и на батчах из того же корпуса, который использовался для обучения. Нужны отдельная проверочная выборка и несколько запусков, чтобы делать сильные выводы о стабильности и обобщении.

## 12. Что именно в этом эксперименте считается «взломом и починкой»?

Никакой взлом готовой Pythia не происходит. «Сломанная» здесь означает **неудачно устроенную дополнительную сеть**, которая должна объяснять внутренние векторы Pythia.

Проблема **не в том, что модель обязательно ничего не восстанавливает**. Реальный вывод показывает, что она уже сохраняет большую часть вариации. Проблема в том, что при неграмотной геометрии и обработке латентов её словарь используется неравномерно: одни признаки получают много примеров и градиентов, другие почти никогда не включаются.

Исправления помогают сети строить более осмысленное разреженное представление: общий фон выносится в `b_dec`, направления имеют контролируемую длину, начальные операции поиска и восстановления согласованы, а активации после отбора неотрицательны.

Но **«0% мёртвых» не равно «2048 осмысленных моносемантических фич»**. Для интерпретируемости пришлось бы изучать, на каких конкретных текстах срабатывает каждый латент, насколько он специфичен и стабилен.

### Ограничения именно этого кода

1. **Нет отдельной валидационной выборки.** Метрики считаются на случайных батчах из той же `X`, что служит для обучения.
2. **Не задано случайное зерно** (`torch.manual_seed(...)`). При повторном запуске результаты могут отличаться.
3. **Используется только одна точка слоя** (`layers[3]`) и один корпус. Нельзя автоматически переносить выводы на все слои и все языковые модели.
4. **Словарь шириной 2048 ещё не интерпретирован.** Нет просмотра токенов, которые активируют конкретные латенты.
5. **Нет специального механизма оживления неактивных латентов** — например, отдельного вспомогательного лосса или повторной инициализации. В конкретном запуске получилось хорошо и без него, но это не универсальная гарантия.
6. **Маска Top-K оставляет максимум 32 ненулевых значения**, а не обязательно 32, особенно после ReLU.
7. **Метрика EV имеет конкретное, не универсальное определение** через дисперсию 512 координат внутри токена. Не следует приравнивать её к доле точно восстановленных значений или к `1 − MSE`.
8. **Картинка `public/task3.png` недоступна в загруженных файлах**; её содержание не участвует в этом разборе.

## 13. Главные связи между понятиями: как собрать всё в одну картину

### Связь 1. Текст → активации

Pythia обрабатывает токены и создаёт контекстные векторы длины 512. Хук получает эти векторы на выходе выбранного блока. Модель Pythia **не меняется**.

### Связь 2. Активации → разреженные признаки

SAE получает каждый вектор `x`, вычисляет 2048 оценок, оставляет максимум 32. Получается разреженный код `acts`, где каждая ненулевая координата — «включение» некоторого выученного латента.

### Связь 3. Разреженные признаки → реконструкция

Декодер складывает соответствующие 512-мерные направления, умноженные на силы активаций. Получается `x_hat`, который должен быть близок к `x`.

### Связь 4. Реконструкция → градиенты → обучение

MSE измеряет, насколько `x_hat` отличается от `x`. Autograd находит производные, Adam обновляет параметры. На следующем шаге сеть обычно может восстановить похожие примеры лучше.

### Связь 5. Две разные метрики → две разные стороны качества

- **Explained Variance** в этой реализации говорит о том, насколько мала дисперсия ошибок относительно исходной дисперсии.
- **Dead Latents Ratio** говорит о том, какая доля словаря не использовалась в последние 500 шагов.

Хорошее восстановление **не гарантирует**, что все признаки нашли работу. Поэтому нужны обе метрики.

## 14. Вопросы для самопроверки (и ответы)

**1. Почему `X` имеет 512 столбцов, но 65 024 строки?**

Потому что каждая строка — один токен в контексте, а его внутреннее представление содержит 512 чисел. Получено 512 последовательностей по 127 сохранённых позиций: `512 × 127 = 65 024`.

**2. Почему после энкодера 2048 чисел, но активны только 32?**

2048 — количество возможных латентов словаря, 32 — число наибольших значений, пропущенных через Top-K. В исправленной версии после ReLU ненулевых значений может быть меньше 32.

**3. Что изменяет `optimizer.step()`?**

Все зарегистрированные параметры SAE, для которых имеются градиенты: `W_enc`, `b_enc`, `W_dec`, `b_dec`. Параметры Pythia в этот оптимизатор не переданы.

**4. Почему `mean(dim=0)` для `X.shape=[65024,512]` даёт 512 чисел?**

Потому что усредняет первую ось — 65 024 наблюдения — **отдельно по каждой из 512 координат**.

**5. Если EV = 82,9%, означает ли это, что 82,9% чисел восстановлены точно?**

Нет. Это результат отношения дисперсии ошибок к исходной дисперсии, вычисляемых определённым способом. Он ничего напрямую не говорит о проценте точно совпавших чисел.

**6. Почему `Dead Latents = 27.2%` — проблема, даже если EV высокая?**

Потому что значительная часть из 2048 потенциальных латентов ни разу не дала ненулевой активации в оценочном окне; словарь используется неполно.

**7. Почему `W_enc = W.T.clone()` не означает, что веса навсегда связаны?**

Потому что создаётся самостоятельная копия со своими градиентами и обновлениями Adam. Равенство гарантировано только в момент инициализации.

## 15. Одним абзацем — что произошло

Ноутбук взял 512 последовательностей текста, через предобученную Pythia получил **65 024 внутренних вектора по 512 чисел**, создал отдельную сеть SAE с **2048 возможными латентами** и ограничил число используемых латентов для одного вектора до **не более 32**. Он дважды обучил SAE по 1000 шагов: сначала с неудачной архитектурой, затем с центрированием входа, согласованной инициализацией, ReLU и нормировкой декодера. В сохранённом запуске качество по EV выросло с **82,9% до 84,4%**, а доля латентов, не давших ни одной ненулевой активации в последних 500 шагах, упала с **27,2% до отображаемых 0,0%**. Главный результат — не просто немного лучшее восстановление, а гораздо более полное использование словаря признаков.
